Friday, 4pm, New York. The closing bell rings and every stock price in the country freezes until Monday. On-chain, nothing stops. The tokenized stocks trades straight through the weekend, priced off a reference that has not updated in two days. Anyone can see the gap, and almost nobody has built anything that acts on it.

That is most of this asset class right now. Tokenized equities landed on-chain faster than the tooling did, so the agents, baskets, rebalancers and onboarding flows that will decide how people actually trade them mostly have not been written yet. ### Main Track: Tokenized Stocks Products & Agents

Build something people would actually use with tokenized stocks on BSC.

An autonomous agent, a trading interface, a portfolio tool, a dashboard, a Telegram bot, an MCP server, an SDK: attack it from whatever angle suits you. The deliverable is a working project, not a deck. Agents are welcome and expected, and are scored on how well they are built rather than on the PnL they could print, we don't track it for this edition.

#### The Rules of the Track

*   At least one of **bStocks**, **Ondo** or **xStocks** has to be central to what you submit.
*   Cross-asset products are in scope, including pairing a tokenized equity leg with crypto or stablecoins.
*   Spot only. Perps are out.
*   **BSC mainnet only.** Dry-run with the Transaction API while you build, then demo with small live amounts. Teams fund their own wallets, and a few dollars is enough to prove the flow works.

#### The Stack



* Component: RWA Data API
  * What it gives you: The tokenized stocks layer: token and platform lists, on-chain price against the underlying reference price, search by ticker, company profile with attestation reports, market status and next open time, sector filters (Magnificent 7, AI Chips, ETF, Buffett Portfolio).
* Component: Market API
  * What it gives you: Real-time prices, candlesticks and token analytics across tokenized equities and crypto pairs. The research and signal layer.
* Component: Trading API
  * What it gives you: Cross-DEX aggregated quotes, swaps and approvals, with built-in MEV protection.
* Component: Transaction API
  * What it gives you: On-chain simulation and broadcasting, so you can dry-run every call before you commit real funds.
* Component: Wallet API
  * What it gives you: Balances, positions and portfolio state across chains.
* Component: DeFi API
  * What it gives you: Protocol information, TVL, APY rankings and on-chain positions, plus unsigned calldata for deposit, redeem and LP across BSC DeFi.
* Component: b402 Payments
  * What it gives you: Pay-per-call payments, for agents that buy data or inference from other agents.
* Component: Agentic Wallet / Wallet Skills
  * What it gives you: The AI execution layer. Optional, heavily weighted in scoring and tied to a special prize.
* Component: BNB Agent Studio
  * What it gives you: One-prompt deployment of a persistent on-chain agent: wallet provisioning, ERC-8004 identity, ERC-8183 task interface and managed cloud runtime, with the MCP server auto-registered into Cursor or Claude Code. Optional, tied to a special prize.
* Component: BNB Chain
  * What it gives you: Execution venue: PancakeSwap and BSC tokenized-equity liquidity.


Combining API modules in a way that looks like it should not work but does is exactly what we are hoping to see.

#### Ideas to Build



* Build: Natural-language strategy agent
  * What it does: Reads a strategy in plain English ("rotate into defensives when volatility spikes"), then writes and executes the rules itself.
* Build: Market-hours arbitrage
  * What it does: Tokenized equities trade around the clock while the underlying market is shut.
* Build: Cross-protocol arbitrage
  * What it does: Prices the gap between two representations of the same underlying, for example bStocks against Ondo.
* Build: On-chain vs reference price monitor
  * What it does: The RWA Data API returns both prices. Track the spread and act on it.
* Build: Auto-DCA and rebalancing
  * What it does: Buys into a tokenized stock basket on a schedule, rebalances on drift thresholds.
* Build: Earnings-calendar agent
  * What it does: Positions ahead of scheduled events and flattens afterwards.
* Build: TradFi-crypto portfolio agent
  * What it does: Holds a target equity/crypto ratio and rebalances as correlation shifts.
* Build: "Buy your first stock on-chain"
  * What it does: Card to tokenized equity in under a minute, no seed phrase in sight.
* Build: One-tap thematic baskets
  * What it does: AI, semis, energy, with transparent on-chain composition.
* Build: MCP server or SDK wrapper
  * What it does: Makes the Binance Web3 API one-line callable from any agent framework, or straight from Agent Studio.


### What to Submit

#### 1\. Your Project

A working project built on one or more Binance Web3 API modules, and optionally Agentic Wallet or Wallet Skills.

*   A public repository.
*   A demo video, four minutes or less (strongly recommended but optional)
*   A deployed link, or instructions a judge can follow.

#### 2\. A Developer Experience Report

Most hackathons do not ask for one. This one does, and it is worth a quarter of your score.



* What we want to know: Onboarding
  * How long from opening the docs to your first successful API call, and where you got stuck.
* What we want to know: Documentation issues
  * Which page had the error, and where on it. Vague feedback does not count.
* What we want to know: API pitfalls
  * Error messages that made no sense, edge cases that bit you, latency. Be specific.
* What we want to know: AI stack feedback
  * Did you use Wallet Skills, Agentic Wallet or the CLI? What worked, what did not, what is missing.
* What we want to know: Tokenized-stock specifics
  * Liquidity depth, slippage, behaviour outside traditional market hours, the gap between on-chain and reference price, and how the bStocks, Ondo and xStocks versions of the same thing differ in practice.
* What we want to know: Redesign suggestions
  * If you were the engineer behind the developer platform, how would you rebuild it so someone can make a call the moment they land?
* What we want to know: Requested capabilities
  * Endpoints, SDK support, features or tooling you want added.


Perfunctory or AI-generated reports are not accepted, the goal is for us to see what worked or not so we won't be able to do anything if you generate this. AI-assisted code is completely fine.

### How You're Judged

Scores are pooled after each judge has worked through every project on their own.



* Criterion: Technical implementation
  * Weight: 30%
  * What we look at: Does it run, and how deep does the integration go? Modules used, error handling, how it holds up.
* Criterion: Creativity & originality
  * Weight: 25%
  * What we look at: Were the APIs used in ways nobody expected? Does this already exist five times over?
* Criterion: Developer Experience Report
  * Weight: 25%
  * What we look at: Specific, actionable, honest, no fluff. Includes the AI stack section.
* Criterion: Product quality & UX
  * Weight: 20%
  * What we look at: Is it usable by the people it is for? Would it bring non-crypto-native users on-chain?
